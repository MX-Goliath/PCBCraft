# Память при редактировании — 21.10.2026

## Причины роста и исправления

1. История хранила неограниченное число полных Document. В схемах каждое
   изменение клонировало исходный Altium-файл в base64, SourceRecord и изображения.
   Теперь исторический source, records и ресурсы изображений разделяются через Arc;
   изменения ресурсов используют copy-on-write. Формат JSON v1 остался прежним.
2. История ограничена 128 снимками и 64 МиБ консервативной **оценки редактируемых
   снимков на документ**. Действует первый достигнутый предел; на больших схемах
   число доступных шагов меньше 128. Старые снимки удаляются первыми, ревизии
   остаются монотонными. Ближайший одиночный oversized-снимок сохраняется даже
   сверх бюджета, чтобы последняя операция оставалась отменяемой. Это не лимит
   всей RAM процесса: открытые документы, единственный native-архив, библиотеки,
   шрифты, GPU и резерв аллокатора учитываются отдельно. Значения можно менять
   через History::with_limits; настройки UI для лимитов пока нет.
3. TextureHandle изображений больше не хранятся бессрочно в egui temp data:
   frame cache освобождает неиспользуемые текстуры после закрытия/скрытия/замены.
   Те же изображения на соседних кадрах используют прежние texture IDs.
4. PCB-cache удаляет неиспользуемые triangulations после одного пропущенного
   кадра вместо хранения до 256 устаревших preview/region записей.
5. Изменения шрифта переиспользуют свободные font slots; скрытые подписи,
   sheet font и отдельные шрифты pin numbers при этом учитываются как ссылки.
   Копирование текста/компонента удерживает только нужные изображения;
   удаление последнего использующего изображение объекта освобождает его
   live-resource, сохраняя доступность изображения через Undo.
6. Закрытие документа очищает его Properties draft/dialog. Saved snapshot,
   clipboard и открытые библиотеки имеют собственное назначение; данные, которые
   ещё нужны им, не удаляются принудительно. Учёт размеров Undo/Redo кэшируется
   при переключении известных снимков и не сериализует документ на каждом Undo.

## Измерения

Linux x86_64, Rust 1.90.0, debug build. Схема Phase1.SchDoc из TI PMP23595
загружена только из локального каталога вне Git. Использован memory_stress
с System allocator, считающим **живые выделенные байты**, и Linux VmRSS.
Измеряется модель/история, без GUI; RSS включает резерв malloc.

До исправления: после 200 переключений hidden одного текста —
1 954 279 943 байта живых выделений и 2 493 669 376 байт RSS.
После закрытия документа живые данные освобождались, но RSS оставался около
2,49 ГБ: ОС-показатель сам по себе не доказывает удержание живых объектов.

После исправления, в десятичных МБ (1 МБ = 1 000 000 байт):

| Сценарий | Повторы | Живые МБ в конце | RSS МБ в конце | Снимков |
|---|---:|---:|---:|---:|
| Переключение видимости | 600 | 19,65 | 30,92 | 9 |
| Изменение текста | 400 | 19,65 | 30,88 | 9 |
| Изменение размера шрифта | 400 | 19,65 | 31,39 | 9 |
| Undo/Redo | 600 | 10,98 | 19,33 | 1 |
| Правка без изменений | 600 | 9,87 | 18,66 | 0 |
| Preview без commit | 600 | 9,87 | 19,29 | 0 |
| Вставка/удаление | 300 пары | 20,77 | 32,98 | 9 |
| Открытие/закрытие | 60 | 9,87 | 33,32 | 0 |

В тесте visibility живые данные одинаковы на шагах 50–600; в текстовых
правках после прогрева также наблюдается плато. После закрытия во всех
восьми пробах остаётся около 4 КБ живых выделений процесса-пробы.
В font-пробе таблица выросла с 14 до 16 определений и не росла далее.

GUI Xvfb/Mesa проверен отдельно на копии editing-demo: 200 переключений
Comment visibility в Component Properties, Undo/Redo, Save собственного JSON,
закрытие вкладки и выход. RSS: 158,89 → 159,16 МБ (основной объём — backend,
шрифты и GUI, поэтому эти числа нельзя напрямую сравнивать с модельной пробой).
Пользовательские оригиналы и TI-файлы не менялись.

## Повторение и регрессии

```sh
cargo run --locked -p eda-io --example memory_stress -- /path/to/input.SchDoc 600 visibility
```

Режимы: visibility, text, font, undo-redo, noop, preview, insert-delete,
open-close. Проба печатает JSONL, не записывает входной документ и работает
также с собственным JSON. На платформах без /proc RSS будет null;
счётчик живых выделений работает независимо от /proc.

Проверены 122 workspace tests, cargo fmt --all -- --check,
Clippy workspace/all-targets с -D warnings и build workspace/all-targets.
Новые регрессии покрывают лимиты истории/ветвление/oversized Undo,
Arc-sharing и освобождение native assets, font-slot reuse, ресурсы clipboard,
удаление изображений с Undo/Redo и освобождение текстур/triangulation caches.
Исходные старые JSON/схемы и библиотеки продолжают проходить IO round-trip tests.

Полные локальные отчёты: <local-report-directory>/memory-validation-2026-10-21/.
Они и исходные проекты TI не включены в Git. Проверены перечисленные сценарии
на Linux; профиль Windows и счётчики GPU VRAM в этот отчёт не входят.
